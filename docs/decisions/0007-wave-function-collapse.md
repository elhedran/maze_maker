# Context

The game is an endless maze, generated as the player moves. Ian first described the approach as "quantum annealing". What he described is Wave Function Collapse (WFC), and that is the name we use. Ian's past experience is that it has to be built in steps, starting with the probability table.

# Decision

- Mazes are generated by WFC over a set of tiles. Every cell starts with all possible (tile, orientation) options. Collapsing a cell narrows its neighbours' options using an **adjacency table** (the probability table) of which (tile, orientation) can sit next to which, and how likely each is.
- Ian's description of the table: rows are what's in a cell plus its orientation; columns are what could be next to it, with their orientations.
- The world is infinite. Only the area around the player is generated, extended as the player moves.
- Build order: first the adjacency table and a tool to inspect it, then a tool that generates sample maps from it, then the game ([DR-0008](/decisions/0008-adjacency-tool-first.md)).

# Alternatives considered

- **Classic maze algorithms** (recursive backtracker, Prim's, ...). Simple and always solvable, but no tile-level variety, and no natural way to extend forever with local rules.
- **Noise-based generation.** Infinite and cheap, but little control over local structure.
- **Quantum annealing** (an optimization method). Not what is meant; noted here to avoid confusion.

# Consequences

Follow-up decisions are needed, each likely major and each with its own record:

- grid shape (square, hex, ...);
- how the side or direction of a neighbour is represented in the table;
- weights versus allowed/forbidden adjacency;
- how contradictions are handled (backtracking, restart, repair);
- determinism and persistence: does the same place always produce the same maze, and is the world kept when the player walks back?

Infinite WFC has known problems where newly generated areas meet old ones. The team should research this before the game phase.
